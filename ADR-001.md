# ADR-001: Streamlit Inference Frontend and Practical Official Dataset

## Status

Accepted

## Context

The project needs to demonstrate image processing clearly while remaining runnable on a local Windows machine. The original KaggleHub route can require a very large archive, and putting model training inside the UI would make demonstrations slow and fragile.

## Decision

Keep Streamlit as the only frontend and make it inference-only. Train the U-Net offline with scripts or the notebook, save a versioned/reproducible checkpoint, and let the app load it for live uploaded-image inference. Use the smaller official Task 1 bundle as the default practical source and retain Kaggle/KaggleHub as optional sources.

## Options considered

### Separate React frontend and Python API

Pros: stronger separation and a conventional production web architecture.

Cons: additional build tooling, serialization contracts, deployment complexity, and less useful overhead for an educational image-processing project.

### Live model training inside Streamlit

Pros: one interface for all actions.

Cons: slow, resource-intensive, easy to interrupt, difficult to reproduce, and confusing for a presentation focused on inference.

### Streamlit for offline training and live inference

Pros: simple local workflow, fast demonstrations, one Python stack, clear separation of batch research from inference.

Cons: the user must train or obtain the checkpoint before U-Net inference is available.

## Why this option is best now

It directly supports the project’s image-processing and presentation goals while avoiding unnecessary frontend infrastructure. It also makes the experiment artifacts visible and auditable.

## Consequences

- The app must clearly display whether the benchmark and checkpoint exist.
- Training commands and artifact provenance belong in the README.
- Deployment requires a separate approved model-artifact strategy.
- Classical methods remain available when TensorFlow or a checkpoint is unavailable.

## Risks and mitigations

- **Slow full training:** keep 20/100/500 modes and document GPU use.
- **Dataset mismatch:** save source, counts, seed, and split manifest.
- **Overclaiming:** keep non-diagnostic warnings in README and UI.
- **Large files:** ignore datasets and model binaries in Git.

## Revisit triggers

Revisit this decision if the project needs multi-user access, persistent patient records, a public API, authenticated deployment, or a frontend team that requires a separate TypeScript client.
